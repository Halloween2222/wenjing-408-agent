## 1. 本周目标

1. 优化直接解析与引导模式 Prompt。
2. 扩展 Cache 计算工具并核对固定案例。
3. 保证引导模式不泄露最终答案或工具数值。
4. 过滤联调样例、演示数据等非权威来源。
5. 明确条件不足、未命中和模型调用失败时的处理。

## 2. 模型配置

本地复制 `backend/.env.example` 为 `backend/.env`，填写自己的 Key：

```dotenv
LLM_API_KEY=your-key
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-flash
LLM_TEMPERATURE=0.1
LLM_MAX_TOKENS=2400
LLM_TIMEOUT_SECONDS=60
```

配置说明：

- `deepseek-flash` 作为课程演示默认模型，满足当前免费额度和响应速度要求。
- 温度设为 `0.1`，降低计算题和固定格式回答的随机性。
- 单次回答上限 `2400` tokens，避免引导模式生成冗长解析。
- 超时 60 秒；底层 HTTP 客户端最多重试一次。
- 前端可通过 `X-User-LLM-Key` 临时使用自己的 Key；该值不写入日志、不持久化，也不进入响应。
- API Key 只能保存在本地或部署环境变量中，禁止提交到 GitHub。

## 3. Prompt 与质量策略

### 直接解析

固定为“结论 → 已知条件 → 关键公式 → 分步计算 → 校验 → 易错点”：

- 先指出用户答案是否正确，减少模棱两可。
- 计算题必须写单位和关键中间量。
- 工具已核验时以工具数值为准。
- AI 与题库答案冲突时保留双方差异，不覆盖题库答案。

### 引导模式

- 不向模型提供标准答案、题库解析和工具数值。
- 每轮只给一个最相关提示，再提出一个可回答的小问题。
- 有 `user_answer` 时优先指出一个具体错误，不一次性完成整题。
- 服务端二次检查选项、最终数值和工具结果；发现泄露时替换为安全提示。
- 只有用户发送“我已主动选择查看答案”后才进入完整讲解。

### 来源边界

`citations` 只展示同时满足以下条件的题库来源：

- 题库核验状态为 `verified`；
- `source_ref` 非空；
- 来源不含“联调、演示、示例、测试、待替换、QA 基准、非真题、团队验收”等占位标记。

非权威来源仍可用于内部联调时解释题目，但不会作为外部引用返回。
个人资料回答只标注“用户提供的个人资料切片”，不会伪造教材页码。

## 4. 计算工具

`backend/app/services/agent_tools.py` 现在返回三种状态：

- `ok`：参数完整，计算有效；
- `insufficient`：题型已识别，但缺少或存在冲突参数；
- `not_applicable`：本轮不需要该工具。

当前确定性覆盖：

| 题型 | 固定案例 | 核验结果 |
|---|---|---|
| 四路组相联 | Q001 | 1024 行、256 组、组索引 8 位、Tag 18 位 |
| 两路组相联 | Q002 | 1024 行、512 组、组索引 9 位 |
| Cache 平均访问时间 | Q003 | 串行模型 15 ns |
| 直接映射 | Q004 | 256 行、索引 8 位、块偏移 6 位、Tag 18 位 |

工具不再用“猜一个数”兜底。参数不足时返回缺失字段，例如缺少块大小时直接要求用户补充。

## 5. 固定案例修改前后对比

测试条件和问题文本保持固定，均使用 `deepseek-flash`。

| 案例 | 修改前 | 修改后 |
|---|---|---|
| Q001 直接解析 | 答案 8 位正确；工具只返回行数、组数、组索引；把“QA 基准用例”作为引用返回 | 答案和 8 位正确；工具同时核验块偏移 6 位、Tag 18 位；非权威来源不再进入 `citations` |
| Q001 引导模式 | 没有泄露最终答案；但仍返回联调样例引用 | 只指出“路数/组数混淆”并追问下一步；工具结果为空、引用为空 |
| Q003 平均访问时间 | 模型答案为 15ns，但没有工具结果参与核对，引用仍是待替换样例 | 工具识别串行模型并返回 15ns；讲解定位 14.5ns 使用了同时访问模型；引用为空 |
| 未命中且无资料 | 仍调用模型，生成条件式推理 | 不再调用模型；明确说明未命中、不能给出可核验答案，也不会编造出处 |
| 条件不足 | 没有统一处理，依赖模型自行追问 | 工具返回缺失条件；不调用模型补条件，直接要求用户补充 |
| 模型调用失败 | 返回通用 502 | 返回稳定错误码、`retryable=true` 和 `Retry-After: 5` |

实际复测摘要：

```text
Q001 直接解析：应选 B，组索引 8 位，工具与题库一致，citations=[]
Q001 引导模式：只提示区分“路数/组数”，未给最终选项，tool_result=""，citations=[]
Q003 直接解析：你给出的 14.5ns 是同时访问模型；本题串行模型为 15ns，tool_result 已核验
未命中无资料：明确拒答，citations=[]，tool_result=""
```

## 6. 异常处理

### 条件不足

条件不足不是“未命中”。如果已找到题目，但缺少计算所需参数，返回缺少的具体字段，不调用模型补造条件。

### 未命中

`question_id=null` 且没有 `context_chunks` 时，直接返回固定说明：

- 当前未命中题库；
- 无法给出可核验答案；
- 不编造标准答案、真题年份和教材页码；
- 请用户补充完整题干或资料。

### 模型调用失败

模型未配置：`503 llm_not_configured`。

模型超时、网络错误、空响应：`502 llm_upstream_error`。

错误响应包含：

```json
{
  "detail": {
    "code": "llm_upstream_error",
    "message": "模型服务暂时不可用，请保留当前内容后重试。",
    "retryable": true,
    "retry_after_seconds": 5
  }
}
```

前端应保留当前题干和对话，引导用户稍后重试，不应把模型失败显示成“未命中题库”。

## 8. 已知边界

- 计算工具目前覆盖固定验收题型：组相联、直接映射、Cache 平均访问时间。
- 非标准中文表述或新增计算题型会进入 `insufficient/not_applicable`，不会盲目计算。
- 来源真实性采用保守过滤：无法确认的外部来源不展示，宁可返回空引用。
- `/api/chat` 当前为非流式接口，保持 Apifox 冻结契约不变。
