## 三、 协作流程
- **建库前**：各自本地初始化项目。
- **建库后**：
  1. `git clone` 仓库。
  2. 切个人分支：`git checkout -b feature/xxx`。
  3. 提交代码并提 PR 给 TL 审核，**严禁直接 push `main`**。
  4. 独立模块完成即可提 PR，无需等全员提交。依赖其他未合并 PR 时写清依赖关系；最终先合并基础 PR，再更新并审查依赖它的 PR。
  5. 答疑原型 HTML 放到 `docs/prototypes/`，标为离线演示。接入真实前端时复用现有 Vue 组件、API 封装与状态管理，先协调共同修改的文件；预设回复不算真实接口已完成。
  6. 此接口文档 PR 只用于审阅修订内容；确认后由叶凯乐同步 Apifox 与 Mock，再通知相关成员按同一版本联调。

   - 未命中：`https://m1.apifoxmock.com/m1/8972811-8778665-default/api/search?apifoxResponseId=342552720`
   - 对话：`https://m1.apifoxmock.com/m1/8972811-8778665-default/api/chat`
   - 上传：`https://m1.apifoxmock.com/m1/8972811-8778665-default/api/upload`
3. **核心逻辑**：本地保存问答历史；在 `utils/` 中实现长文本切片，请求 `/api/chat` 时填入 `context_chunks`。

6. **资料与重试**：上传文本先预览修正、确认后保存；失败保留草稿，重试成功避免重复消息。Mock 三态、错误状态与真实服务分别验收。
7. **当前依赖**：答疑界面接入以 PR #2 最新分支为基础，与郑志銮协调 AnswerPanel、ResultView 等共享组件；这里记录依赖，不表示 PR #2 已合并。

# Apifox 在线文档与调试使用手册

## 一、 核心功能
- **Apifox**：接口契约管理平台。统一定义前后端数据结构，集成接口文档、调试、Mock与测试功能。
- **Mock**：自动生成符合契约的模拟数据。用于前后端解耦，前端无需等待后端开发即可获取数据。

## 二、 界面介绍
- **左侧导航栏**：接口列表。
- **中间详情区**：
  - 请求参数：入参定义（字段名、类型、必填项）。
  - 返回响应：出参定义（不同业务状态对应的 JSON 结构）。
- **右侧调试区**：点击右上角“调试”唤出，用于发送请求。

## 三、 操作流程
1. **选择接口**：左侧点击目标接口。
2. **查看状态**：中间区域切换不同响应状态（如 成功/未命中）。
3. **调试运行**：点击「调试」，在 URL 栏填入 Mock 地址或本地后端地址。
4. **发送请求**：在 Body 栏输入 JSON 参数，点击「发送」。
5. **获取响应**：查看下方返回的 HTTP 状态码及 JSON 数据。

## 四、 使用思路

**前端**
1. 查阅接口“返回响应”，确定 UI 渲染所需字段。
2. 在代码中向 Mock URL 发起请求。
3. 将响应的 JSON 数据绑定至页面变量进行渲染。

**后端 / Agent**
1. 根据“请求参数”定义路由并做入参校验。
2. 执行业务逻辑（查库、调模型等）。
3. **按契约封装出参**：返回的字典/对象字段名必须与“返回响应”完全一致。
4. 启动本地服务，在 Apifox 填入 `localhost` 地址，自测输出结果。

**测试 (QA)**
1. 依据“返回响应”示例编写测试用例。
2. 在调试面板修改参数，验证正常流与异常流（漏传/错传）的处理结果。

## 五、 避坑指南
- **报错 `invalid apifoxResponseId`**：Mock 链接过期。回平台重新复制。
- **报错 `ECONNREFUSED`**：请求地址错误。确认是填了 Mock 链接还是本地服务地址。
- **跨域报错 (CORS)**：浏览器拦截。需在前端项目配置代理。
- **红线**：严禁私自修改字段名。所有接口变更需报备 TL 并更新平台文档。
